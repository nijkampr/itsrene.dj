# ADR-0004: Content as data, synced by GitHub Actions

**Status:** Accepted · 2026-07-06

## Context

The current page hard-codes four hand-picked SoundCloud embeds, including a "LATEST" claim that is now 11 months stale. Nothing on the page updates itself. Meanwhile SoundCloud exposes the full 32-track catalog as a **zero-auth RSS feed**:

```
https://feeds.soundcloud.com/users/soundcloud:users:1009672477/sounds.rss
```

The brief demands: *nothing on the page can go stale by itself*, and the repo should showcase automation on a static host.

## Decision

**Lists live in JSON; a scheduled GitHub Action keeps them fresh; vanilla JS renders them.**

1. `data/sets.json` — the set catalog. Generated by `.github/workflows/sync-sets.yml`: a scheduled workflow (weekly cron + manual dispatch) fetches the RSS, transforms to JSON (title, date, permalink, curated flags preserved via merge), and commits only when the feed changed.
2. `data/gigs.json` — IRL gig history. Hand-maintained; a gig is added by editing JSON, never HTML.
3. Curation stays human: `sets.json` entries support hand-set fields (`featured`, `vibe: melodic|techno|hard|chaos`, `note`) that the sync merges over, never overwrites.
4. Rendering is progressive enhancement: `js/main.js` fetches the local JSON and renders cards. A `<noscript>` link to the SoundCloud profile covers the no-JS case.
5. No client-side calls to third-party APIs for content (CORS and rate limits live in CI, not in visitors' browsers).

## Consequences

- "Latest set" is computed, never claimed. The staleness class of bug is structurally gone.
- The Action is a portfolio piece: cron + idempotent commit + merge-don't-clobber on a static site is exactly the "showcase of what's possible" the brief asks for.
- Adds the repo's only workflow dependency on an external feed shape; if SoundCloud kills RSS, the JSON simply stops updating and the site keeps working (graceful decay, not breakage).
- Client-side rendering of the list costs one fetch and ~50 lines of JS. Accepted under ADR-0001's "CI generates data, never pages" rule.
